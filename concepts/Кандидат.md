# Кандидат

Кандидат — физическое лицо, индийский специалист, привлекаемый на работу в Россию через платформу.

> [!info] Архитектура данных (D13)
> Введена формальная модель разделения: **candidate** — глобальная сущность, принадлежащая индийскому партнёру; **candidate_profile** — профессиональный профиль, привязанный к специализации и вакансии (через `candidate_profile` → `vacancy`). Один кандидат может иметь несколько профилей (в v1 — только один профиль).

## Данные кандидата (candidate)

Общие данные, не зависящие от специализации (3.12). Данные общие для всех профилей кандидата:

- ФИО, дата рождения, гражданство, телефон, email, фото

## Профиль кандидата (candidate_profile)

Заполняется рекрутером [[Роли и суброли|индийского партнёра]]. Профиль привязан к специализации — один кандидат может иметь несколько профилей (D13, в v1 только один):

**Профессиональные данные (3.13):**
- Должность, разряд, опыт, текущий работодатель, образование, номер Aadhaar

**Дополнительные сведения (3.14):**
- Языки, примечания

## Документы кандидата

Полный перечень см. в [[Документы]]:

- Загранпаспорт
- Aadhaar (индийский ID)
- Диплом / сертификат квалификации
- Страховой полис
- Результаты медицинского обследования

Доступна загрузка видео с демонстрацией профессиональных навыков (MP4/MOV/AVI, до 500 МБ на файл):

В ФТ от 9.04:
- загрузка видео — **key feature** (3.20)
- просмотр видео клиентом — **base** (3.26)

## Пул кандидатов

При добавлении кандидата в заявку партнёр Индии может выбрать существующего `candidate` из своего агентства и создать для него новый `candidate_profile` (3.32, D13). Для повторного выбора доступны только кандидаты, которые:

- не находятся на рассмотрении;
- не одобрены ни одним клиентом.

> [!warning] В ФТ есть опечатка приоритета
> Для пункта 3.32 в исходном файле указано `nive to have`; по смыслу это `nice to have`.

## AI-обработка профиля и документов

При загрузке документов система может:

- автоматически определять тип документа и раскладывать его по соответствующим слотам (3.33);
- автозаполнять данные кандидата, если они ещё не заполнены (3.33);
- сверять данные документа с уже заполненным профилем и показывать предупреждение при расхождениях (3.33);
- автоматически переводить текстовые описания кандидата, введённые на английском, на русский для клиента и партнёра РФ (3.34).

## Жизненный цикл (13 статусов)

Подробная модель описана в [[Статусная модель кандидата]]:

1. Подобран
2. Документы загружаются
3. Документы готовы
4. На проверке РФ
5. На согласовании
6. Одобрен
7. Оформление визы
8. Вылетел
9. Прибыл
10. Оформление в РФ
11. Работает

**Терминальные статусы:**
- Отклонён — не прошёл проверку или [[Согласование кандидата|согласование]]
- Закрыт (замена) — выбыл, требуется замена

## Согласование

Клиент просматривает данные кандидата (3.24), документы (3.25) и видео (3.26), затем одобряет (3.27) или отклоняет с выбором причины из [[Глобальные настройки|справочника]] (3.28). При отклонении слот в заявке остаётся открытым для добавления нового кандидата (3.4). Подробнее — [[Согласование кандидата]].
