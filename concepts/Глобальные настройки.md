# Глобальные настройки

Раздел [[Кабинеты|кабинета администратора]] для управления общесистемными параметрами платформы.

## Дефолтные значения SLA

Три независимых SLA в рабочих днях (см. [[SLA и светофор]]):

| Параметр | Описание | Приоритет |
|----------|----------|-----------|
| SLA на принятие заявки (ИН-партнёр) | Срок от назначения до нажатия «Взял в работу» (10.1) | nice to have |
| SLA на подбор кандидатов (ИН-партнёр) | Срок от принятия до завершения подбора (10.2) | nice to have |
| SLA на принятие заявки (РФ-партнёр) | Срок от назначения до нажатия «Взял в работу» (10.3) | nice to have |

Дефолтные значения переопределяются вручную при назначении партнёра на конкретную [[Заявка|заявку]] (2.28–2.29).

Если дефолтное значение не задано, поле SLA при назначении партнёра остаётся пустым и требует ручного ввода (10.1–10.3).

## Справочник профессий

Управление списком доступных профессий: добавление, редактирование, деактивация (10.4).

Для каждой профессии:
- Название на русском
- Название на английском
- Список разрядов (на русском и английском), если для профессии применимы разряды

Справочник заполняется администратором вручную. Используется при создании заявки клиентом (2.17) — произвольный ввод профессии недоступен. Справочник должен соответствовать перечню профессий на `migrakvota.gov.ru`.

**Приоритет:** key feature

> [!question] Достаточно ли ручного поддержания актуальности справочника профессий, или нужна автоматическая синхронизация с `migrakvota.gov.ru`? (10.4)

## Справочник регионов

Отдельный справочник регионов РФ: добавление, редактирование, деактивация (10.7).

Для каждого региона:
- Название на русском
- Название на английском

Справочник содержит предзаполненный список субъектов РФ и используется при создании [[Заявка|заявки]].

## Справочник причин отклонения кандидата

Управление списком причин отклонения: добавление, редактирование, деактивация (10.5). Используется клиентом при отклонении [[Кандидат|кандидата]] (3.28).

**Приоритет:** key feature

## Текст согласия на обработку ПД

Загрузка и редактирование текста согласия кандидата на обработку персональных данных (10.6). Автоперевода нет — текст хранится и отображается as-is. Администратор самостоятельно обеспечивает нужный язык.

Используется при первичной авторизации кандидата (1.4) — требование 152-ФЗ.

**Приоритет:** key feature

> [!question] Используется ли системный текст согласия всегда, или в части сценариев индийский партнёр сам подтверждает наличие офлайн-согласия и принимает риски на себя? (1.4, 10.6)
