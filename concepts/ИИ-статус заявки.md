# ИИ-статус заявки

ИИ-статус — функция аналитической обработки данных заявки, предоставляющая клиенту человеко-читаемую сводку, прогноз завершения и оценку рисков на основе агрегированных данных из всех модулей платформы.

## Источники данных

ИИ-статус формируется на основе агрегации данных из следующих источников:

| Источник | Данные |
|---|---|
| **Поля заявки** | Должность, разряд, кол-во, регион, жильё, дата выхода, зарплата, особые требования |
| **Статусная модель** | 11 внутренних статусов → 6 клиентских; 40+ событий с таймстампами |
| **SLA / Светофор** | 3 SLA-таймера (принятие ИН, подбор ИН, принятие РФ); цвет (🔵🟡🔴🟢) на каждом этапе |
| **Кандидаты** | N из M добавлено/одобрено/отклонено; 13 статусов каждого; причины отклонений |
| **Документы** | Статусы 5 кандидатских документов на каждого кандидата; сгенерированные документы (РНР, СНИЛС, ИНН, МВД, страховка) |
| **Pipeline** | Текущий этап из 7; время на каждом этапе |
| **Чек-лист оформления** | Прогресс по шагам (Стандарт — 5 шагов, Премиум — 10+ шагов) |
| **Этапы РНР** | 16 шагов регуляторики — какие пройдены, какие в процессе |
| **Партнёры** | Назначенные организации и сотрудники; их история SLA-соблюдения |
| **Коммуникация** | Активность в 3 чатах на кандидата; последние сообщения |
| **Бенчмарки** | AS IS: 185–210 дней, Target: 120–140 дней |
| **Пакет услуг** | Стандарт / Премиум — влияет на объём чек-листа |

## Выводы ИИ

### 1. Natural Language Summary

Перевод сухого статуса заявки в человеко-читаемый абзац на русском языке:

> «Заявка на 5 сварщиков в Москву находится на этапе "Подбор". Индийский партнёр предложил 7 кандидатов, 3 уже одобрены. Оставшиеся 2 слота — в работе. Прогноз: первые 3 специалиста выйдут к 20 июня, полная заявка закроется к 15 июля. Рисков нет — все SLA соблюдаются.»

### 2. Прогноз завершения (Predictive ETA)

На основе текущего этапа, оставшихся шагов РНР, SLA-трендов и исторических данных — **предсказанная дата выхода кандидата на работу** с диапазоном уверенности:

- Дата завершения: `2026-07-15`
- Диапазон: `15–22 мая`
- Уверенность: `72%`

> [!info] Точность прогноза
> На старте платформы уверенность будет низкой. Прогноз улучшается по мере накопления исторических данных по завершённым заявкам.

### 3. Оценка рисков

Анализ комбинации факторов:

| Фактор риска | Сигнал |
|---|---|
| SLA в жёлтой/красной зоне | Риск задержки этапа |
| Частые отклонения кандидатов | Риск затягивания подбора |
| Документы на проверке дольше нормы | Риск на этапе оформления |
| Партнёр систематически нарушает SLA | Риск на будущих заявках |
| Квота не одобрена в срок | Блокер для начала подбора |

**Пример вывода:** «Заявка в зоне риска — индийский партнёр отстаёт от SLA на подбор на 4 дня. Рекомендуем эскалацию.»

### 4. Bottleneck-детекция

Определение «узкого горлышка» — какой этап тормозит всю заявку и почему:

> «Основная задержка — этап РПИРС (30 дней). 2 из 5 кандидатов ожидают медобследование.»

### 5. Качество пула кандидатов

Агрегация по всем кандидатам заявки:

- % с полным комплектом документов
- % одобренных с первой попытки
- Топ причин отклонений
- Среднее время от подбора до одобрения

**Пример вывода:** «Из 8 предложенных кандидатов 5 одобрены (63%). Главная причина отклонений — недостаточный опыт (3 случая).»

### 6. Рекомендованные действия

Контекстные next steps для клиента:

| Тип | Пример |
|---|---|
| Ожидание | «Ожидается: одобрение 2 кандидатов — проверьте карточки до 12.04» |
| Требуется действие | «Требуется ваше действие: согласуйте КП от партнёра Индии» |
| Внимание | «Внимание: через 5 дней истекает SLA на подбор» |

## Структура ответа ИИ

AI-processing микросервис возвращает структурированный JSON:

```json
{
  "summary": "текст на русском",
  "predicted_completion": "2026-07-15",
  "confidence": 0.72,
  "risk_level": "medium",
  "risk_factors": ["SLA подбор ИН — отставание 4 дня"],
  "bottleneck": "РПИРС — 2 кандидата ожидают",
  "recommended_actions": ["Проверить карточки 2 кандидатов до 12.04"],
  "candidate_stats": {
    "total": 8,
    "approved": 5,
    "rejected": 2,
    "pending": 1
  }
}
```

## Техническая реализация

- **AI-processing микросервис** — агрегирует данные из всех сервисов, формирует промпт
- **GigaChat SDK** — генерирует natural language summary и классифицирует риски
- **Входные данные** — агрегированный JSON с полями заявки, статусами, SLA, кандидатами, документами
- **Кэширование** — результат кэшируется на 1–4 часа (в зависимости от активности по заявке)
