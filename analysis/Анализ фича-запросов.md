# Анализ фича-запросов

**Дата:** 2026-04-03

## 1. Управление квотами (QUOTA-01)

**Покрытие:** 🟡 Частично — регуляторика описана, UI отсутствует.

Что нужно доработать:
- UI-флоу получения и отслеживания квоты
- Видимость статуса квоты для клиента
- Статусная модель квоты (подана → на рассмотрении → одобрена → отклонена)
- Нотификации по смене статуса
- Обработка сценария отказа в квоте

## 2. Заключение договора на площадке (CONTRACT-01)

**Покрытие:** 🔴 Не покрыто — договорный процесс отсутствует полностью.

КП ≠ договор. Необходимо проработать:
- Конструктор договора vs типовой шаблон
- Стороны и подписанты (кто подписывает от каждой роли)
- Интеграция с ЭДО (электронный документооборот)
- Момент заключения договора в pipeline
- Типы договоров (рамочный, на конкретную заявку, с агентством)

## 3. Прозрачная статусная модель e2e (STATUS-01)

**Покрытие:** 🟡 Частично — есть client view и candidate model, но отсутствуют:
- Partner RF view (что видит рекрутер РФ)
- Partner India view (что видит агентство)
- Admin сводный view (общая картина)
- Cross-role timeline (единая шкала событий по заявке)

## Приоритет

**CONTRACT-01** → **QUOTA-01** → **STATUS-01**

Договоры — наивысший приоритет, так как без них невозможно формализовать отношения между сторонами. Квоты блокируют начало подбора. Статусная модель улучшает прозрачность, но не блокирует работу.
