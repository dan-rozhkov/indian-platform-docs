# Экраны — Администратор (MVP + Target)

Роли: **Супер-админ** и **Менеджер проекта** (суброли MVP). Интерфейс на **русском языке**.

Администратор управляет всей платформой: организациями, пользователями, заявками, назначением партнёров, согласованием КП, квотным процессом, справочниками и глобальными настройками.

## Детальное описание экранов (MVP)

### 1. Дашборд

**Тип:** Dashboard
**Приоритет:** MVP

**Ключевые элементы:**
- Счётчики: входящие заявки, активные сделки, просроченные SLA
- Заявки в разрезе статусов (12.1)
- Воронка кандидатов (12.2)
- Активность партнёров и просроченные SLA (12.3)
- Подсветка просроченных по SLA заявок (2.15)
- Быстрые действия: «Назначить партнёров», «Переназначить партнёра»

**Требования:** 2.15, 2.24, 12.1, 12.2, 12.3

---

### 2. Список заявок

**Тип:** List
**Приоритет:** MVP

**Ключевые элементы:**
- Таблица всех заявок платформы: клиент, должность, кол-во, статус, назначенные партнёры, SLA
- Фильтрация по статусу, клиенту, партнёру, дате
- Поиск по названию/должности
- Визуальный индикатор SLA по каждой заявке (2.30)
- Переход в детальную заявку

**Требования:** 2.24, 2.25, 2.30

---

### 3. Детальная заявка

**Тип:** Detail
**Приоритет:** MVP

**Ключевые элементы:**
- Полная карточка заявки (2.25)
- Параметры заявки: все поля брифа
- Информация о клиенте
- Назначенные партнёры (организация + конкретный сотрудник)
- Настройка SLA для индийского партнёра: (1) на принятие заявки, (2) на подбор кандидатов (2.28)
- Настройка SLA для российского партнёра: на принятие заявки (2.29)
- Визуальный индикатор SLA (2.30)

**Требования:** 2.25, 2.28, 2.29, 2.30

---

### 4. Назначение партнёров

**Тип:** Form
**Приоритет:** MVP

**Ключевые элементы:**
- Назначение индийского партнёра: выбор организации и конкретного сотрудника (2.26)
- Назначение российского партнёра: выбор организации и конкретного сотрудника (2.27)
- Настройка SLA при назначении (дефолтные значения из глобальных настроек, переопределяются вручную)
- Уведомление клиента о назначении партнёров (2.6)
- Уведомление индийского партнёра с указанием SLA (2.7)
- Уведомление российского партнёра с указанием SLA (2.8)

**Требования:** 2.6, 2.7, 2.8, 2.26, 2.27, 2.28, 2.29

---

### 5. Список организаций

**Тип:** List
**Приоритет:** MVP

**Ключевые элементы:**
- Таблица организаций: название, тип (клиент/партнёр РФ/партнёр Индии), статус верификации, кол-во пользователей
- Фильтрация по типу и статусу
- Переход в карточку организации
- Управление пользователями организации

**Требования:** 1.8, 1.10, 1.11

---

### 6. Карточка организации

**Тип:** Detail
**Приоритет:** MVP

**Ключевые элементы:**
- Реквизиты организации
- Список пользователей с ролями
- Добавление пользователя: ввод email + роли → генерация реферральной ссылки → email-приглашение (1.14)
- Повторная отправка приглашения / сброс пароля (1.15)
- Удаление сотрудника из организации (1.16, key feature)
- Редактирование реквизитов (1.9, key feature)

**Требования:** 1.9, 1.14, 1.15, 1.16

---

### 7. Согласование КП

**Тип:** Detail
**Приоритет:** MVP

**Ключевые элементы:**
- Просмотр поступившего КП от индийского партнёра
- Статус КП: на рассмотрении / утверждено / отклонено
- Передача КП клиенту на рассмотрение
- Уведомление клиента о поступлении КП (2.9)
- При отклонении КП клиентом — уведомление админа для переназначения партнёра (2.11)
- Переназначение индийского партнёра при отклонении КП (2.31)
- Просмотр данных отстранённого партнёра (режим только чтение, 2.32, nice to have)

**Требования:** 2.9, 2.11, 2.31, 2.32

---

### 8. Список кандидатов

**Тип:** List
**Приоритет:** MVP

**Ключевые элементы:**
- Таблица всех кандидатов платформы: ФИО, должность, заказ/заявка, статус, партнёр, клиент
- Фильтрация по статусу, заявке, партнёру
- Переход в карточку кандидата

**Требования:** 3.2

---

### 9. Справочники

**Тип:** Settings
**Приоритет:** MVP

**Ключевые элементы:**
- Управление справочником профессий: добавление, редактирование, удаление. Для каждой профессии: название на русском, на английском, список разрядов (10.4, key feature)
- Управление справочником причин отклонения кандидата: добавление, редактирование, удаление (10.5, key feature)
- Управление текстом согласия на обработку ПД: загрузка и редактирование (10.6, key feature). Автоперевода нет — текст хранится as-is

**Требования:** 10.4, 10.5, 10.6

---

### 10. Квотный процесс

**Тип:** Checklist
**Приоритет:** MVP

**Ключевые элементы:**
- Статусная модель квоты: Отправлена → Подтверждена подписью → На рассмотрении МВК → Включена в формирование квоты → Включена в проект приказа / Отклонена МВК (6.1)
- Создание чеклиста этапов квотного процесса (6.3, key feature)
- Редактирование чеклиста (6.4)
- Настройка ключевых дат по каждому статусу квотной заявки (6.5)
- Загрузка инструкции для каждого этапа (6.6)
- Загрузка шаблона документа для каждого этапа (6.7)
- Ручная смена статуса квотной заявки (6.8) — единственный способ, автоматических интеграций нет
- Уведомление клиента при смене статуса квотной заявки (6.2)

**Требования:** 6.1, 6.2, 6.3, 6.4, 6.5, 6.6, 6.7, 6.8

## Замечания

- Ни один из 16 экранов ещё не создан в прототипе — вся админская часть требует полной разработки
- Экран 10 (Квотный процесс) — полностью ручной, без автоматических интеграций; смена статуса выполняется вручную администратором
- Экран 4 (Назначение партнёров) — критичный для MVP, без него невозможно начало работы по заявке
- Экран 7 (Согласование КП) — включает переназначение партнёра при отклонении КП клиентом (2.31), что является ключевым workflow
- Экран 15 (Управление интеграциями) — вынесен на отдельную суброль «Администратор интеграций», не входит в MVP
- Все экраны должны быть на **русском языке**
